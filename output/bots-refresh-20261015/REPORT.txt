Implemented /bots refresh in the workspace; validated with detached local and Studio fixtures.
The running Studio play session and active account were not used to execute the command.
Nothing was published. Production Studio sources and the local .rbxl were not replaced.

Behavior
- Existing server-side user-creator/group-owner authorization; exact /bots refresh parser.
- Single pending command consumed before the next simulation request batch/step.
- Existing BotPopulation.Capital[Kind] determines new bot equity; all participant categories,
  retiring agents and close-only markets are included. Players/clearing/archive accounts excluded.
- Realized and unrealized reported P&L start at zero. Original position Entry stays intact;
  PnlEntry establishes the new accounting cost basis, including partial closes and scale-ins.
- CapitalAdjustments records actor, sequence, step/time, capital amount, cash change, prior
  realized/unrealized P&L and the retained PnlBaseline. Existing double-entry notional cash,
  equity, inventory, volume, FIFO and player-statistics audits remain enforced.
- Detached accounting preview is committed with the fenced world checkpoint before applying
  to live bot objects. Existing strategy state, positions, orders, protections and priorities
  survive; already accepted player requests retain their queue position during the save.
- A durable monotonic receipt prevents replay; ambiguity pauses and reloads the durable result.
- Checkpoint V17 reads older formats and prevents older builds from settling the new baseline.

Activation / local-save requirement
Studio was left in its existing Play session. The new command is not active in that session.
1. Stop Play when ready. This was not done automatically to avoid interacting with the active account.
2. In Studio Edit mode, run the contents of InstallBotsRefresh.luau in the Command Bar.
   The installer checks all eight destination sources before writing, refuses Play mode,
   and refuses unexpected source changes. It performs no checkpoint writes or publication.
3. Save the local place, then start a new play session to load the updated modules.
4. Thereafter the owner can use /bots refresh without restarting the simulation. The concise
   success notice includes bot count and signed total capital adjustment and appears only after save.

Installation itself does not run the refresh. Do not resume a V17 checkpoint with an older engine.
The local .rbxl has intentionally not been resaved during an active Play session.
